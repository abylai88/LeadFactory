# Технический аудит — 08.10.2026

## Исходное состояние

Исходный проект доступен для чтения/изменения. Обнаружены NestJS 12, Prisma 7 с адаптером pg, модели User/Workspace/WorkspaceMember/Company/Lead и первоначальная SQL-миграция. Python/FastAPI имел только /health и один тест. Frontend, CRM endpoints, discovery и enrichment отсутствовали. Рабочих поисковых компонентов для повторного использования не было.

В PATH отсутствовали Python, Docker, PostgreSQL; был Node.js 24.21.0. Для проверки Python создано .venv на базе доступного Python 3.12.14. PostgreSQL получен как готовый пакет embedded-postgres, запущен локально. Репозиторий .git отсутствовал: git-коммит не создавался.

## Архитектурное решение

Next.js → NestJS → Prisma → PostgreSQL. NestJS → FastAPI → Nominatim/Overpass и публичные сайты. HTTPX выполняет запросы к заранее заданным провайдерам, Parsel разбирает HTML. Для недоверенных URL сайта используется небольшой транспорт на стандартном http.client с привязкой к проверенному IP — это предотвращает повторное DNS-разрешение между проверкой и подключением.

Существующие сущности и миграция сохранены. Redis, браузерный кластер, AI scoring и готовая вторая CRM не добавлены: для одного оператора это усложнило бы запуск без пользы. Поле aiScore оставлено для совместимости, но не заполняется выдуманными значениями. Owner — локальный технический пользователь, не найденный лид.

## Оставшиеся ограничения

Локальное использование, без authentication/authorization. Один процесс каждого сервиса. Публичный OSM не полный реестр коммерческих компаний. Контакты извлекаются как опубликованные строки, без проверки личности, актуальности и доставляемости. Перечень ограничений и запуск приведены в README.
