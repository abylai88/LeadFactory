# LeadFactory MVP

Рабочая локальная CRM для поиска компаний в открытых источниках. Исходные NestJS, Prisma, PostgreSQL и Python/FastAPI сохранены и дополнены; интерфейс — Next.js. Платных API, LLM, автоматических рассылок и генерации контактов нет.

## Что реализовано

- Workspace API: создание, просмотр, переименование, удаление с каскадом.
- Company API: создание, список, просмотр, редактирование, удаление, фильтр по названию и пагинация.
- Lead API: создание, список, изменение полей/статуса, удаление, фильтры по компании/email/статусу, пагинация.
- Поиск по городу и одной из 14 ниш через Nominatim + Overpass/OpenStreetMap; до 50 компаний за запрос.
- Сохранение OSM ID, ссылки на источник и времени обнаружения. Уникальный ключ workspace + sourceId исключает повторный импорт одного OSM-объекта.
- Извлечение опубликованных email, tel-ссылок и описания с главной страницы и максимум двух контактных страниц; каждому контакту сохраняется источник. Используется Parsel из экосистемы Scrapy.
- Транзакционный импорт, история поисков COMPLETED/FAILED, восстановление статуса прерванного поиска после рестарта backend.
- Русский адаптивный интерфейс: рабочие пространства, поиск, таблицы, ручное добавление/редактирование компаний, добавление лидов, изменение статуса, удаление, история ошибок.
- PostgreSQL в Docker либо настоящий локальный PostgreSQL через embedded-postgres, без установки Windows-службы.
- Скрипты установки, запуска, остановки и тестов. SQL-миграции не сбрасывают существующую базу.

## Быстрый запуск на Windows 10/11 x64

Нужны Node.js 24 LTS и Python 3.12 (с py launcher). Docker необязателен. Интернет нужен для установки зависимостей и получения открытых данных. Освободите порты 3000, 3001, 8000, 5432.

В PowerShell:

```powershell
cd "C:\Users\user\Desktop\LeadFactory-Astra-FIXED"
powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

Откройте **http://localhost:3000**. Создайте рабочее пространство, выберите нишу, укажите город и страну, нажмите «Найти компании». Для сохранённых компаний с сайтом доступна кнопка «Найти контакты». Контакты появятся во вкладке «Лиды».

В текущей папке зависимости уже установлены и сборки выполнены. Повторная установка не нужна, если окружение не менялось. Приложение, оставленное после проверки, останавливается обычным stop.ps1.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\stop.ps1
# Повторный запуск:
powershell -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

Запуск выполняется в скрытых процессах. Логи: `.runtime/*.out.log`, `.runtime/*.err.log`. PID-файл используется только для процессов этого проекта и проверяется по времени запуска. База сохраняется в `data/postgres`; stop.ps1 её не удаляет.

`setup.ps1` не перезаписывает существующий `backend/.env` или `frontend/.env.local`. После смены NEXT_PUBLIC_API_URL пересоберите frontend. Если перенесли проект на другой компьютер, создайте новое Python-окружение: старое `.venv` привязано к исходному интерпретатору.

## Docker вместо локального PostgreSQL

Нужен запущенный Docker Desktop. Не запускайте одновременно оба варианта базы на порту 5432.

```powershell
# Из корня проекта, после setup.ps1:
docker compose up -d postgres
powershell -ExecutionPolicy Bypass -File .\scripts\start.ps1 -ExternalDatabase
# Остановка приложения и контейнера без удаления данных:
powershell -ExecutionPolicy Bypass -File .\scripts\stop.ps1
docker compose stop postgres
```

Docker использует PostgreSQL 16 и отдельный volume `leadfactory_postgres_data`; локальный вариант — PostgreSQL 18.4 и `data/postgres`. Это разные базы, данные между ними автоматически не переносятся. Контейнерный вариант в этой среде не проверен: Docker отсутствует. Миграции используют совместимый с обеими версиями SQL.

## Настройки

`backend/.env.example` содержит DATABASE_URL, PORT, HOST, FRONTEND_ORIGIN, CRAWLER_URL. Значения по умолчанию предназначены для локального компьютера. PostgreSQL и оба backend-сервиса слушают только loopback. Пароль `leadfactory_local` является локальным значением для разработки.

Python читает переменные окружения: NOMINATIM_URL, OVERPASS_URL, CRAWLER_USER_AGENT. Их можно задать в PowerShell перед запуском. По умолчанию используются публичные OSM-инстансы; пользовательский User-Agent позволяет указать собственный контакт оператора. При повышенной нагрузке замените endpoints собственными инстансами. Используйте один процесс Python и один NestJS-процесс: координация и кэш в MVP локальные.

## Проверки

При работающей PostgreSQL:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\test.ps1
```

27 автоматических проверок: Python — 15, backend unit — 1, PostgreSQL integration — 11. Интеграционные тесты создают явно помеченные TEST FIXTURE пространства и удаляют только созданные ими записи. Они подменяют внешний источник для воспроизводимости. Не запускайте тесты одновременно с поиском: NestJS startup восстанавливает прерванные поиски в базе. Для CI используйте отдельный DATABASE_URL и предварительно примените миграции.

В отрицательном тесте отката транзакции NestJS может напечатать ожидаемую PrismaClientValidationError. Признак результата — итог Jest, а не эта намеренно вызванная ошибка. Python выводит предупреждение об устаревшем httpx-адаптере Starlette TestClient; тесты проходят.

Живая проверка 08.10.2026: запрос software + Berlin, Germany сохранил 10 OSM-объектов и 8 контактных записей из OSM. Enrichment OPTIMAL SYSTEMS обработал две реальные страницы и добавил 14 опубликованных email. Итого 10 компаний, 22 контакта; повторный импорт не увеличил число компаний. Это полученные данные, не seed и не демонстрационные выдуманные записи. Записи OSM могут быть устаревшими; наличие объекта не подтверждает текущую деятельность компании.

## Границы MVP

- Локальное приложение для одного оператора. Нет авторизации, ролей и проверки членства в Workspace. Scope workspaceId предотвращает случайные обращения к чужим записям, но не является пользовательской аутентификацией. Не выставляйте порты в Интернет.
- Поиск ограничен справочником ниш, покрытием OSM и пространством города: bounding box для небольших городов либо радиус 20 км для крупных. В результатах возможны пригороды и организации, не подходящие для B2B. Свободного семантического поиска по всему Интернету нет.
- Контакты на общекорпоративном сайте могут относиться к другим офисам/городам. Email не проверяется на доставляемость, имена и должности не угадываются. Статус NEW не означает подтверждённый интерес клиента.
- До трёх HTML-страниц за enrichment, без JavaScript-рендеринга. robots.txt соблюдается. Междоменные редиректы пропускаются: при необходимости укажите конечный официальный сайт вручную. CAPTCHA и ограничения сайтов не обходятся.
- Кэш поисков в памяти на 24 часа (до 200 запросов), интервал геокодирования не менее 1,1 секунды, последовательная обработка. Кэш сбрасывается при рестарте. Нет очереди Redis, фонового планировщика и промышленной отказоустойчивости.
- Публичные провайдеры могут отвечать 429/5xx. Ошибка сохраняется в истории, ложный успешный результат не создаётся. Повторите позже.
- Исходная папка `backend/backend` оставлена на месте и не участвует в сборке. Рабочие файлы — `backend/src`.
- Права на данные OSM (ODbL), права на сайты и лицензии кода — разные вопросы; атрибуция показана в интерфейсе. Автоматических рассылок нет.
